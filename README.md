# dsh-extra-workspaces

给一个 DSH 会话挂上额外的本地工作目录。清单出现在右侧栏的 **会话设置** 页里，并且会作为一条运行时上下文提醒告诉模型——只在清单变化时注入，不是每轮重复。

## 它做什么

- 会话设置页里多出一节 **额外工作区**：添加目录、改别名、写一句备注、删除。添加时**优先用 DSH 自带的目录选择器**（系统弹窗形态）；如果这个 DSH 部署强制使用"网页内浏览"形态（例如启动参数带了 `--trusted-host` 远程可信域名），插件会**跟随官方**，改用与官方工作区流程走同一组宿主接口（`listDirectory` / `createDirectory`）的内置网页选择器——与官方工作区流程同源（`listDirectory` / `createDirectory`），界面沿用网页文件系统的习惯：路径栏旁边直接列出 **盘符快捷链接**（Windows 宿主，后台探测并缓存 5 分钟，当前盘高亮，空光驱/断连网络盘不会卡住对话框）；文件列表**首行的 `../` 返回上一级**；面包屑可跳任意祖先节点（主目录也在里面）；路径栏点"编辑路径"可直接输完整路径跳转；"显示隐藏文件"与"新建文件夹"在底部；官方单层 1000 条上限提示照常显示。最近一次确认的目录会被记住（浏览器本地存储），目录失效时自动退回主目录。弹窗通过 `react-dom` portal 渲染到 `document.body` 并占顶层 z-index，因此会盖在会话设置卡片（含它的拖拽调高亮区）之上，不会被卡片控件抢走点击。界面是响应式的：宽屏是居中的 680×500 对话框，**手机/窄屏（≤640px 或高度 ≤600px）自动变成全屏面板**——去掉圆角、行高与按钮加大到适合触控、输入框用 16px 字号避免 iOS 聚焦缩放、底栏按钮换行、并留出刘海/Home 条的安全区；平板则按可用尺寸收紧留白。这些样式由一次注入的 `<style>` 驱动（CSS 变量 + 媒体查询），注入被拦截时回退到内联的桌面尺寸，功能不受影响。几个细节约定：**"新建文件夹"的输入条固定在列表与底栏之间**，列表再长也不会滚出视野，打开即聚焦，名字为空时"创建"禁用；加载失败、单层超限这类提示固定在底栏上方的状态条里，不会被滚动隐藏；**切换目录后列表自动回到顶部**；输入框里的 Esc 只取消当次输入，弹窗其它位置的 Esc 关闭弹窗。
- 清单按会话保存（`<DSH_HOME>/storages/session_settings/sessions/<会话id>.json`），DSH 重启后同一条会话仍然带着它。
- 清单变化时，模型的最新上下文里出现一条提醒，列出每个目录的别名、绝对路径、备注，并**如实说明当前权限档下能不能改这些目录**。
- 不注册成 DSH 的正式工作区，不改 DSH 本体的任何文件，不挂 DSH 的任何钩子。

## 权限：说清楚，不假装

本插件**不扩大 DSH 允许写入的范围**。DSH 的可写根只有一个：会话自己的工作目录（外加系统临时目录）。所以：

| 会话权限档 | 主工作区 | 额外工作区 |
|---|---|---|
| 仅可查看 | 读得到，改不了 | 读得到，改不了 |
| 工作区可写 | 读得到，改得了 | 读得到，改不了；只读命令能跑，要写文件的命令会被拒绝 |
| 完全权限 | 完全对等 | 完全对等 |

提醒文本按会话**实际**权限档选措辞，所以模型不会以为自己能写其实写不了。

## 规则

- 同一个目录重复添加会被拒绝；
- 与已有条目互相包含（父目录或子目录）也会被拒绝——避免"加了父目录之后主工作区反而变成它的子目录"这种状态；
- 每个会话最多 8 条（可用 `maxWorkspaces` 配置）；
- 目录被删掉或移走不会自动移除，也**不会**被插件主动标注：提醒里不断言目录是否存在（那需要在每步请求里探测磁盘，会把整个 DSH 卡住），面板上的标注只在目录选择器处于"网页内浏览"形态时可用，且含义是"宿主读不到这个目录"。

## 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `maxWorkspaces` | `8` | 每个会话最多几条（上限 64） |
| `reminderLanguage` | `'zh'` | 提醒文本语言（`'zh'` / `'en'`） |

## 安装

包放进 profile 能解析的位置（例如 `link:D:/projects/dsh-plugins/dsh-extra-workspaces`），把它加进 profile 的 `dsh.profile.bundles`，再按 `cordis.patch.yml` 里的那一行把宿主半边挂上。客户端半边由 `dsh.client` 声明自动装配，无需额外步骤。

## 已知边界

- 内置网页选择器是本插件自带实现，不是官方那个对话框组件本身（官方组件只装配到官方工作区流程里，没有对外导出）。但它和官方走同一组宿主接口、同一起点（宿主主目录）、同一套隐藏规则和单层上限，观感与行为跟随官方。
- 只支持本地目录；远程（SSH）工作区未支持。
- 不判断目录是否存在：提醒不断言，请求路径上也不探测磁盘（网络路径的探测会同步阻塞整个进程）。
- 会话设置页仍会显示这一项自带的"默认值/已覆盖"框架，那由页面控制，不由本插件控制。
